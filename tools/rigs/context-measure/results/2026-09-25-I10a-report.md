## Limits

- 14 full lanes per condition on synthetic, easy tasks (100% success in every arm). 0/14 entry-level
  misses is a point estimate: its exact one-sided 95% upper bound is 19.3% (the rule of three gives ~21%). The A/B shows no
  regression and the direction of the miss effect. It cannot certify < 5% the way §7.2's week of live
  traffic would.
- About 12k of the tokens that `inherit` adds are not in the transcript (tool schemas). The first-request
  tokens include them; the per-attachment chars cannot itemize them.

## Reviewer addendum (post-merge review of #809, session 01a0d798-439e)

**D2 split: matches the decision.** `missLevel` classes a `header` or `body` drop as a header read and everything else as entry-level: `count-cap:entry`, `byte-budget:entry`, `not-selected`, `absent-from-index`. For the fixture tasks, `linked` is the needle, the file and the 59 distractors, so a read of a link past the 32-link read counts as an entry-level miss (D2 1b). The gate row is per LAUNCH, the per-read rate is reported separately, and the header flag fires above 25%.

**Hand checks.**
- *Tried to disprove a hit* (ab-off `rounding` r1, session 01a0d7ab-cbf5): the needle 01a0d769-ebe9 is NOT in the first user turn (`<linked count="60" omitted="44">` does not list it), and the off arm's tm8 system prompt is a constant 12,995 bytes for every task, so it cannot carry task ids. The manifest drops it as `count-cap:entry`, and the lane reads it at transcript line 52. The hit stands.
- *Confirmed a non-hit* (ab-on-derived `rounding` r2, plus both authored lanes): the needle appears in neither the user turn nor any tool result before the lane's first `entity context <needle>`. It can only have come from the index in the system prompt, so "listed, header trimmed" (a header read, not gated) is right.

**Excluded rows: each is legitimate, and each is now counted in the table.** The two 0-link replicas were refused by the guard before any measurement. For index-derived replica-01a0d3b2, `pmset -g log` shows the Mac entering Low Power Sleep at 08:38:52Z on 1% battery, 50s after the lane started, and waking at 13:43Z. For ab-on-authored merchant r2, the lane ran zero `tm8` commands (no CLI journal) and wrote no transcript. Its manifest's index is identical to the successful r1 (10,754 bytes, 24 entries), so the index arm built normally and the stall came before Claude's first request. That is consistent with the workspace-trust hang, but not screen-proven. **Both lanes that failed to start were in index-on arms**, and none of 48 index-off launches failed to start; with 53 on-arm launches out of 101, the chance of that is about 28%, so it is not significant. `summarize.mjs --excluded <file>` now prints `launches set aside / attempted (of which: no transcript)` per arm: ab-off 0/14 (0), ab-on-derived 0/14 (0), ab-on-authored 1/15 (1). A failure that recurred in one arm can no longer disappear into "excluded, re-run".

**Cross-lane contamination: a limit on the success comparison, not on the gate.** `resetTask` unticks and reopens the fixture task, but it cannot remove earlier lanes' messages. Every A/B lane's `entity context <task>` returned 1–2 earlier closeouts, one from 07:15, before the A/B started. For example: "roundedBalance added to src/ledger.js … Spec implemented: doc 01a0d769-ebe9 'Balance roun…'". That hands the needle id and the implementation to both arms. In 3 of 42 lanes the needle id reached the lane through such a message before it read the needle. The GATE is unaffected, because an entry-level miss is decided by the manifest (was the id in the prompt?). But "task success not worse than off" (Q2) compares arms that were both given hints, on tasks that were already easy (100% in every arm). For I10b, give each lane a fresh copy of the task (replicate.mjs already copies tasks) so no lane can read another's closeout.

**Verdict on the numbers.** The entry-level gate result (0/14 in each on arm, against 2/14 in off, where the off-arm misses are the stress needle hidden by the linked-names count cap) is measured correctly and can be trusted as a point estimate. As the Limits section says, its exact 95% upper bound is 19.3%, so it shows direction and no regression; it does not certify < 5%. The success parity is weaker evidence than the table suggests, because of the contamination above.
