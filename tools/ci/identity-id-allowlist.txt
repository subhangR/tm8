# The identity_id() allow-list (plan 01a0d9eb §3 W3, F7), read by tools/ci/identity-id-gate.sh.
#
# One line per live reader of the caller's identity, as
#   <root|setting> <object>
# where <root> is `identity_id` (internal.identity_id()), `require_identity` or
# `current_account_id` (the two wrappers that hand the identity on), `setting`
# means the raw tm8.identity_id setting, and <object> is a function
# schema.name(identity args) or a policy / column default / view as
# pg_describe_object prints it. A `setting` reader is found in function bodies,
# policy USING/WITH CHECK, column defaults and view definitions. The gate fails on a live reader missing from this list AND on a line
# here that matches no live reader. `identity-id-gate.sh --list <url>` prints the
# live set.
#
# Adding a line is a security review. Such an object decides for itself whether
# the caller may act, so check that it cannot reach a space other than the pinned
# one (internal.session_space_id(), 227): it goes through a pinned membership
# helper, RLS as tm8_app (a subquery on public.members is itself pinned by
# members_select), node admin (pinned out by space_enter_and_pin), or touches only
# the caller's own account rows. Put the verdict in the trailing comment.
#
# Tags: PIN-HELPER, ACCOUNT, GUARDED, NODE-ADMIN, GLOBAL-CATALOG, STAMP, NEEDS-REVIEW, KNOWN-GAP (see the W3-audit
# matrix in packages/server/test/db/cross-space-token.pg.test.ts).
