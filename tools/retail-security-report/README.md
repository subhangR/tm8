# retail-security-report

Python orchestrator for the Retail Security 2026 research pipeline that lives in
`research/retail-security-2026/` (scripts/, raw/, build/). It runs the same stages the Crawl
Engineer ran by hand on 16 Oct 2026, adds a monthly mode that builds new content for each new window,
and writes a local run report.

Canonical source: `tools/retail-security-report/retail_security_report.py` (+ `spec.json`).
Registered as the tm8 stored tool **retail-security-report**; after editing, sync with
`tm8 tool edit retail-security-report --source @tools/retail-security-report/retail_security_report.py --spec @tools/retail-security-report/spec.json --expect-version <n>`.

## Monthly mode: new content every run

`--stages monthly` (the one-file runner's default) makes each run cover a **new window**: from the
day after the previous run's end date, kept in `build/state.json` (the very first run starts at
`--first-from`, default 1 Oct 2026, so the first report covers a whole month), up to today. The collectors keep only records published
inside that window (`RSR_SINCE`), the `period` stage (`scripts/period.py`) filters, de-duplicates
and clusters them into **new** named incidents, country/theme roundups, leak-site listings (always
marked as claims) and Have I Been Pwned loads, with per-entry sources, statistics, social quotes and
a screenshot list; `build_period_site.py` / `build_period_pdf.py` render them with the same globe,
charts and CSS as the annual report. Outputs:

```
build/periods/<from>_<to>/period.json            every entry with its evidence
build/periods/<from>_<to>/candidates.md          human-readable triage list
build/periods/<from>_<to>/site/index.html        interactive, light + dark
build/periods/<from>_<to>/pdf/Retail-Security-Monthly-<from>-to-<to>.pdf
build/runs/<run-id>/report.md                    what the run did, top entries, ledger state
```

The ledger advances to the window end once the site exists, unless the primary collector (`collect`)
failed or the window holds no dated records. Each collector runs under a time budget two minutes short of
`--collect-minutes` (default 120 in the tool, 150 in the local runner): when it is spent, or Reddit answers
429 twelve times in a row, the collector ends **partial** (exit 0, everything fetched so far kept, the log says
where it stopped) instead of being killed with nothing recorded. A partial or failed `reddit`/`social` stage
becomes a **collection warning** in the run report and the ledger still advances; to redo such a window
completely run again with `--period-from/--period-to` and a larger `--collect-minutes`. Empty
`build/periods/<from>_<to>/` folders left by earlier failed runs (no entries, not in the ledger) are removed
before the next window is built. `--period-from/--period-to` rebuild any window (e.g. the 1–16 Oct 2026
backfill); `monthly-build` skips collection and rebuilds a window from `raw/`. With
`ANTHROPIC_API_KEY` set the entry summaries are written by Claude (`--model`, default
claude-sonnet-5-5) from the evidence titles and checked against the evidence list; without it, or
with `--no-llm`, they are rule-built. Nothing from the annual register is carried over; a window with
no relevant coverage yields a short report saying so.

## Run on your own machine (no tm8, no docker)

One file: `retail_security_report_local.py` (generated by `bundle.py`; it carries the pipeline
scripts inside). Every parameter has a default in the `CONFIG` block at the top of the file; edit it
there or override with flags. Copy it anywhere and run:

```
python3 retail_security_report_local.py                        # monthly: collect the new window, build its site + PDF (~1-2 h, mostly collection)
python3 retail_security_report_local.py --stages monthly-build --period-from 2026-10-01 --period-to 2026-10-16   # rebuild a window from raw/ (~3 min)
python3 retail_security_report_local.py --stages build         # the annual 2026 report from the register (~5 min)
python3 retail_security_report_local.py --stages all           # re-collect since 1 Jan + annual build (~1-2 h)
```

It unpacks `./retail-security-2026/`, creates `retail-security-2026/.venv` with the newest python
3.10–3.13 on PATH (so Homebrew/Debian "externally-managed-environment" never bites and the laptop's own
python is untouched; `--no-venv` to opt out), pip-installs `curl_cffi requests beautifulsoup4 pypdf pymupdf
pillow playwright` there (`curl_cffi<0.14` on macOS: newer wheels need macOS 15) and the Playwright
Chromium. Where Playwright has no Chromium build for the OS (macOS 12 Monterey: "does not support chromium
on mac12") it uses an installed **Google Chrome** or Edge instead (`--browser-channel auto|chromium|chrome|msedge`,
`scripts/rsr_browser.py`); Linux may need one `sudo python3 -m playwright install-deps chromium`. A project folder created by an OLDER runner build is refreshed (its scripts replaced by
the new file's copy, `.runner-build` records the build; raw data, outputs and the ledger stay) so a re-downloaded
runner always runs the current code. The setup ends with one `[setup] checks:` line listing python, every
package, the browser in use, docker and the scripts build. It then
writes the period site, PDF and `build/runs/<run-id>/report.md`. Options: `--project <dir>`, `--refresh-scripts`,
`--no-install`, `--no-venv`, `--browser auto|local|docker|none`, `--first-from`, `--force`. Without a launchable
browser the browser stages are skipped with the reason in the report; collection, site, verify and report still
run. If `curl_cffi` cannot load, the collectors fall back to plain `requests` and the run report carries a
**transport warning** (Reddit may answer less without browser-impersonating TLS) so a thin harvest is never
read as a quiet month. Every browser call has a hard watchdog (`RSR_HARD_TIMEOUT`), the console check gets one
retry and is skipped rather than failed when Chromium wedges, and inside Docker Chromium starts with
`--single-process --no-zygote` (its sandbox crashes the first renderer there). After editing anything
under `research/…/scripts/`, regenerate with `python3 -P tools/retail-security-report/bundle.py`.

## Run through tm8

```
# via tm8 (run options before the name)
tm8 tool run --cwd <repo-root> retail-security-report --stages verify
tm8 tool run --cwd <repo-root> retail-security-report --stages build
tm8 tool run --detach --cwd <repo-root> retail-security-report --stages all --publish \
    --artifact 01a145a6-12b8-7534-813c-3df84910a49a --task 01a1451b-7c20-7917-b15e-2aa749a9b7fe

# directly
python3 -P tools/retail-security-report/retail_security_report.py --stages build
```

Stages: `collect`, `reddit`, `social` (refresh raw/), `period` (monthly clustering), `geo`, `shots`,
`site`, `check`, `pdf`, `verify`, `report` (always), `publish` (only with `--publish`). Sets:
`monthly`, `monthly-build`, `all`, `build` (default), `collect`, `verify`. Monthly flags:
`--period-from`, `--period-to`, `--no-llm`, `--model`.

Output: `research/retail-security-2026/build/runs/<run-id>/report.md` + `run.json` + one log per
stage; `build/runs/latest.md` mirrors the newest report. Exit 0 = all ok, 1 = a stage failed
(report still written), 2 = project dir not found, 64 = bad arguments.

## Needs

- Python 3 with curl_cffi, bs4, pypdf, PyMuPDF (fitz), Pillow.
- A browser backend for shots/check/pdf: `--browser local` = python-playwright (`pip install playwright && python -m playwright install chromium`);
  `--browser docker` = the image `mcr.microsoft.com/playwright:v1.64.0-noble` with `/opt/tm8/prod/node_modules` readable (tm8-server). `auto` prefers docker when its image is present.
- `tm8` on PATH and write access for `--publish`.

## What it does not do

The ANNUAL incident register, source index and statistics (`scripts/report_incidents.py`,
`report_sources.py`, `report_stats.py`) are analyst-written; `build`/`all` rebuild them as they
stand and never auto-add. The MONTHLY report is machine-built from the window's evidence: it says
what was reported, by whom and when, with a confirmed/reported/roundup status, and does not replace
an analyst's reading of a story. No logins, no paywall bypass, no cart/checkout, no Tor; nothing
under raw/ or build/ is committed.
