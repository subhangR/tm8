Overview & information architecture

tm8 already has a phone layout: the web app forks into a one-surface shell under 500px with a drawer, real-history back, and five first-class phone screens. It is honest and it works. It is also a website. This document designs the thing the phone shell could never be — a native app with its own stacks, sheets, gestures and notifications, that holds several servers at once and gives every kind in the graph a screen worth opening.

What the current phone shell taught us

The web shell's rulings are measured, not tasteful, and the native design keeps every one that was about meaning and replaces every one that was about browser limits.

Ten principles

  1. Jobs, not kinds, in the tab bar.Chats (talk to agents), Work (what is moving), Inbox (what needs you), Browse (everything else). Kinds live one level down.
  2. Every entity has an address and a screen.Any id from any server opens; the registry picks the body; a kind without a body gets the generic page, never a dead end.
  3. Status is color + word.Pills carry a dot and a word in the tm8 ramp. Liveness never lies: live, waiting, exited, stale are different words.
  4. Agents are peers with provenance.Humans round, agents rounded-square. Who did a thing is always on screen.
  5. One scope at a time, shown at the top-left.The space button names where you are; one tap shows every server and space you can reach.
  6. Chat is the home of work.A turn shows what the agent did to the graph (the receipt), not a wall of tool JSON. Streaming is a live row, not a spinner.
  7. Native where it counts.Platform type, haptics, sheets with detents, large titles on iOS, Material 3 bars on Android, predictive back, share sheet, Dynamic Type.
  8. Offline is a state, not an error.Everything read is cached per server; writes queue with a visible pending pill; a server that cannot be reached says so in the switcher.
  9. Nothing invented client-side.Counts the node did not return are absent, not zero. Costs the runtime did not report are absent, not $0.
  10. Same words as the web.Labels come from the kind registry (Tasks, Sessions, Teammates…). A link copied on the phone opens on the desktop and reads the same.

Owner ruling · 2026-10-28 · hierarchy is visible"In the current phone app, for sessions and others, the tree structure is not shown in the list — in the app it must be shown." Every kind list is a tree whenever any row has children (sessions launched under a root session, subtasks, sub-docs, child stories): expanded to depth 2 by default, a disclosure chevron on parents, 20pt indent per depth with a hairline guide, a count summary on a collapsed parent ("3 children · 2 live"). Tree is the default layout for Sessions, Tasks, Docs and Stories; entity pages show the parent chain and a Children tree. The web drawer already expands children in place; the phone list dropped it, and this design restores it everywhere.
Decision · styleThe app ships in tm8's current default style — neutral surfaces, system type, the gold accent — because that is what the product defaults to today (owner ruling 2026-10-14) and because the system face is what "native" means on each platform. The ATELIER paper-and-ink theme stays available as a space style the app can paint from. The status ramp is unchanged in both.
