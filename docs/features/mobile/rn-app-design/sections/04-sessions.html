04 · Sessions

Sessions and everything that runs: terminal, launch, fleet, tools, connectors, containers

Everything that runs in tm8 gets a live, honest screen of its own: an agent's work session, a plain terminal, a tool run, a container or a worktree lane. The web phone shell made the session page an immersive terminal with a "Messages door". The native app splits that page into Live · Transcript · Context · Stats · Discussion, moves the terminal to its own full-screen route with a real keys bar and landscape mode, adds a cross-server Running now fleet, and turns the launch dialog into a native sheet where every refusal names its cause. Every word comes from tm8's own session model: a row says working, waiting for you, stale or crashed, never the raw process status. Every list nests launched sessions under the session that launched them.

Work › Sessions: the launched-by tree

The Sessions segment of the Work tab uses lane 05's chrome (large title, segments, filter chips) and this lane's rows. Each root session carries the sessions it launched as children (the launched_by edge, treeParentOf). The list opens expanded to depth 2, and every row has its own verdict word.

Filters. The brief sketched "Live · Waiting · Mine · Exited". tm8 already rules on this partition (Spec D1 §5.3, owner 6 Oct): Running · Interrupted · Completed · Stopped. Every session lands in exactly one of the four, they map to the server's own filters (SESSION_TAB_FILTERS), and the counts add up. So the four are kept and composed with the registry's two toggles, Mine ("Assigned to me") and Needs me. "Live" is Running, "Waiting" is Needs me, and "Exited" is the other three. "Running" stays a tab word and not a row word: live is only the count word ("● 13 running").

The session page: Live

One screen per session, with five segments. Live shows what the agent is doing now. It is a projection of the transcript tail (the newest tool call with no result yet, the last few calls), the PTY activity signal, pending forms and the last message the session posted. The tail read's age is always shown, and nothing is guessed.

Session page, Live: anatomy. iOS, light. The Coordinator's own session, with its eight lanes as children. /[server]/[space]/session/[id]?seg=live

  1. Back names where you came from: Work, Inbox, a task, or Running now. iOS edge swipe and Android predictive back pop it.
  2. Share · more: Copy link and Open on web, plus the verbs for this row's state (sessionVerbsOf). While it works: Complete… and Terminate…. A stale session adds Resume and Mark lost.
  3. Eyebrow and title: kind, short id, and its origin. A launched child shows its parent chain here instead ("launched by ◆ TM8 Mobile app · Coordinator").
  4. Verdict row: the row word, duration, and the context number, which only shows a % when capacity is known. A second line names the teammate, the exact model id and the agent mode.
  5. Chips: claimed task(s), worktree branch (or "shared checkout" / "scratch"), and the server. Every chip pushes its page.
  6. Segments: Live · Transcript · Context · Stats · Discussion. They are route state (?seg=), so a link can open on any of them. The header collapses into the top bar on scroll.
  7. Now: the newest tool call that has no result yet in the transcript tail, plus PTY activity. "no result yet · 8s" is a fact, not a claim about why it is waiting.
  8. Recent: the last finished tool calls as chat-kit tool cards, each with an output tail. Tap one to open it in the Transcript.
  9. Launched: the Children tree (the owner ruling). Each child has its own verdict, and a tap pushes that session.
  10. Last message it posted on its own anchor or its task. On an exited session, this is where the receipt shows.
  11. Dock: Terminal (a full-screen route) and Message. It changes with state: Resume on an interrupted or stopped session, Reopen on a completed one, and disabled-with-reason when there is nothing to attach to.

The web made the session page immersive (CONTRACT §5: the header was hidden so the terminal kept its height, and Messages became a "door" to a Discussion sheet). Native overturns the immersion and keeps the meaning. The terminal gets its own full-screen route, so the page no longer has to give up its header to the canvas. The door becomes the Discussion segment: same thread, same count, addressable. Ruling 8 (Messages above Linked) still holds; Linked lives at the foot of Context.
"Waiting for you" is server truth only: process idle plus pending forms. presentSession's needs-you is "designed-but-dormant (R8) — no detector ships", so the app never infers a permission prompt from silence. It does show the neutral fact "no result yet · 2m" for an in-flight call, because both halves of that fact come from the transcript and the PTY.

Transcript · Context · Stats · Discussion

Scrolling any segment collapses the header into the top bar (title + verdict) and pins the segments. Transcript reuses the chat kit's turns, tool cards and steps. Context is the launch manifest. Stats is the post-mortem. Discussion is the thread on the session's anchor.

Transcript, offlineThe agent's own transcript (execution.transcript), cached per server. Turns marked "user" carry no person's name, because the transcript records only user/assistant and never claims an author. Offline, Terminal is disabled with its reason. Queued offline writes are v2 (lane 08), so Message is disabled offline in v1. …/session/[id]?seg=transcript
Context: the launch manifestDark. Everything that went into the launch, each row tagged with its role and where it came from (launch · teammate · task). Rows the viewer can't read arrive as a count. Credentials name the source kind and label, never a secret. The system prompt opens a read-only viewer (proposed route), and Linked follows below. …/session/[id]?seg=context
Stats: the post-mortemAndroid, light. Read once from the finished transcript and never polled. Absent is not zero: an unreported token count renders "—" and the total is then labelled a floor. There is no cost and no exit code, because neither is recorded for work sessions. …/session/[id]?seg=stats
Discussion, keyboard up: messaging a closed sessionThe web's Messages door, now a segment. Each message carries the server's delivery outcome. "✓ delivered live" went to the PTY. Sent after completion, the message is stored on its anchor and the sender is told so in the node's words (recipient_session_closed). …/session/[id]?seg=discussion
The honesty rules of session-stats.ts carry over unchanged: hollow is not zero, exact digits rather than "18.2k" in a post-mortem, no cost (no per-model rate table exists for work sessions), and no exit code (the work_session state carries none). Delivery is three-valued: accepted is not "delivered". The row shows "delivering…" until the delivery row settles.

The terminal

v1 scope (lane 08): the terminal is read-only in v1, so watching, selection, scrollback, landscape and reconnect ship first, and typing with the keys bar is v2. The terminal is a full-screen route (/session/[id]/terminal). The canvas is near-black in both themes. A mono chrome strip states the verdict, the grid size and any armed modifiers. Below it sits the keys bar for the keys a phone keyboard lacks. Whether you may type is server truth (driveMode); whether you may watch is shareMode.

Portrait, typing: a harness prompt (v2, proposed)Lane 08 ships the terminal read-only in v1, so this input state, the keys bar and the keyboard are v2. iOS, dark. Reviewer runs in safe mode and Claude Code stopped at its own permission prompt. tm8 cannot see this prompt (R8), so it is answered here: ↓ and Return on the keys bar. Ctrl is sticky: it arms, the next key spends it. "50×22" is honest about width; under 60 columns, full-screen tools wrap. /[server]/[space]/session/[id]/terminal
View only, selection and scrollbackAndroid, light. The canvas stays dark. A session launched by another member, with drive: owner, cannot be typed into, and the bar says why and by whose dial. A long-press selects text with handles; the floating toolbar copies. Scrolled back, a pill returns to the live line. …/session/[id]/terminal
Landscape: full screenWatching works in v1; the keys bar is v2. Rotating hides every piece of chrome except the strip and the keys bar. The PTY is resized to 101 columns and the strip's width note changes from "full-screen tools will wrap" to "wide enough for tools that assume 80 columns". The safe-area inset on the island side is kept. …/session/[id]/terminal (landscape)
ReconnectingAndroid, dark. The socket dropped, so the last frame stays on screen, dimmed and timestamped, and is never presented as live. Keys (v2) are disabled with the reason given. If the verdict turns to exited, the canvas swaps for the outcome screen (see States). …/session/[id]/terminal
The keys bar keeps the web's measured choices (mobileKeys.ts): esc, tab, sticky ctrl and alt, and arrows that respect DECCKM. It adds / - | ~ paste, which iOS hides on the second keyboard page, plus Aa for the font ladder 9–15 (13 is the shared default). The width readout is kept on purpose: "A phone at 390px gets somewhere in the forties. Saying so is the point."

Launch

Launching is a sheet over the screen it came from: a task, any entity, or a teammate. Every control maps to a tm8 session spawn flag: --teammate --task/--about --workdir --base-ref --access-mode --reasoning-effort --credential-source --memory --context --interaction-profile. On Android the same form is an M3 full-screen dialog, with the same semantics: it has no address, Back dismisses it, and your picks are kept.

Launch sheet (top)Launched from a task. Teammates are ordered recents first, then by name. A teammate the node can't launch is drawn disabled with the mechanism ("No persisted model for Claude Code"). Effort and access start at Default, so opening the sheet never pins a posture. /[server]/[space]/launch?subject=[id]
Launch (lower half) and a refusalAndroid, light: a full-screen dialog. Each access mode has one line of explanation. Credentials (one row per provider, opening the picker) sit above Memories. Memories ride this session only. The node's refusal renders in the dialog with its cause, what did not happen, and the remedy. Launch stays disabled with that reason. /[server]/[space]/launch
Credential pickerDark, stacked over the launch sheet, one tab per provider. Options the policy or the account excludes are drawn disabled with the reason in their own text: a hidden option would read as "does not exist". Auto states a prediction, not an outcome. sheet in /launch (no address)
The web's canLaunch rule is kept: every refusal names its mechanism ("Pick a teammate — a session runs as a persona, never anonymously"). A refusal from the node renders in the sheet and never as a toast apology (T5-5). After an accepted launch the sheet closes, a toast reads "Launching Worker…", and the row appears as starting under its task and at the top of Work › Sessions, journalled by clientMutationId. Dispatch stays a separate action whose label says the sheet's settings are not used.

Running now: the fleet

Every live session across every signed-in server, grouped by server and then space. As with Inbox's "All servers", "what is running" is a question about the person, not about the active space. Collapsed roots keep the state remembered for this list.

The rules carried over from the web: entity = full screen and pickers = sheets (CONTRACT §4); "sheet content is never the subject of a share", which is why the credential picker has no address while /launch keeps the overview's route; one surface at a time; the Back Contract (stack cap 12, cold link lands on Work › Sessions); disabled-with-reason everywhere (L6, "a refused control is not a control").
