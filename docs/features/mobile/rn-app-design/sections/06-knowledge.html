06 · Knowledge

Knowledge, media and people

Docs, files, drawings, graphs and artifacts are the parts of the graph you read. Memories, skills and spells are what teammates carry (styles are drawn by 02 shell). Members and teammates are who did the work. On the web phone shell only the doc and the artifact got real screens; every other kind fell back to the generic page. Here each kind gets a native screen: a doc reader with an outline and a resume point, a source-faithful editor with a formatting bar above the keyboard, viewers chosen by the file type the node declared, a pencil canvas, a graph you can pan, and profiles where the avatar's shape tells you human or agent.

Doc — the reader

The most important screen in this section. Most links into a doc come from somewhere else (a chat receipt, a task's Linked, an Inbox mention), and the reader's job is to put the words first and keep every way out one tap away. Drawn on The Back Contract, v12.

  1. Back names where you came from. "Docs" because this was pushed from the list. A cold link (push, share, widget) opens as [Docs, this doc], so Back still lands on a list, never on nothing.
  2. Share and ⋯. Share sends the web address (https://tm8.sh/#/s/atelier/e/01a17c3e…), so it opens on a desktop too. ⋯ holds Copy link, Open on web, Save as PDF (the web's print path), Pin to Browse and Add sub-doc.
  3. Reading progress. A 2pt hairline under the bar. The app stores your position for each doc id and version on this phone, and the next open offers Back where you left off. When the doc has a newer version, you resume at the heading you were under.
  4. Kind · version · id, title, byline. The byline names the creator and the update time. It never names a "last editor": the contract has no such field (doc-edit G4), and guessing would credit Subhang with Priya's edit.
  5. The body is the doc's markdown, rendered natively. CommonMark + GFM, the same grammar the web renders (kit/Markdown). Headings double as outline targets, keyed by source line like the web's MD_HEADING_ATTR.
  6. Chips inside prose. A chip is a markdown link to an entity's web address, which the app recognises and draws as a chip; the stored text stays a plain link. Tap opens the entity; Back returns to this paragraph, not the top. Long-press shows a preview sheet. A chip for a deleted entity reads struck through and opens its tombstone.
  7. Reader bar (iOS toolbar, hidden while scrolling down, back on scroll up): Outline, Messages (the count is the node's; when it sends none, no number appears), Edit. On Android the same three verbs are the top-bar Outline icon, the ⋯ menu, and an Edit extended FAB.

A wide table scrolls inside its own box, as the web ruled, so the page never pans sideways. The mermaid fence is drawn as a static diagram; tap opens it full screen with pinch zoom. Why the reader works this way. The web ruled on 2026-10-19 that a doc reads full screen and moved its discussion behind a button (MESSAGES_ON_PAGE excludes doc), because Messages under a long body were thirty screens away. The native reader partly overturns that. The reader bar's Messages is always one tap away, and the end of the doc still carries the latest message and Linked, so the overview's "Messages + Linked on every kind" holds without making anyone scroll to discuss. The outline stays a list, not chips (user ruling 2026-08-17: a pill row of long headings could not be scanned). Headings are controls that arrive: tap scrolls to them. Sub-docs are a separate tree, because they are other entities, and following the owner's ruling of 2026-10-28 every list that nests shows the nesting.

Doc — the editor

Edit opens the same doc as markdown source, with the marks shown but dimmed, so what you type is exactly what the node stores. There is no second rich-text model to drift from the web. The formatting bar sits on the keyboard and wraps the selection in marks. @ opens a picker for the entity to reference. Save writes with the version the editor opened (expect-version), so a concurrent edit is refused, never overwritten.

Editor, keyboard up, @ picker (iOS)Typing @ searches the space and suggests matches. Picking one inserts an ordinary markdown link to the entity's web address, and the reader draws any such link as a chip (that is client-side parsing, no new syntax). A skill inserts as [/github](tm8://skill/…), the one reference scheme the node reserves today. The title shows the save state in words: Draft · not saved, Saving…, Saved v13. /[server]/[space]/e/[id]/edit
A save refused by a newer version (Android, dark)The write carried expect-version 12 and the doc was at 13, so the node refused it. The app shows the two versions change by change, in plain words, never as a raw diff dump. Keep both saves yours as a sub-doc, so neither edit is lost. /[server]/[space]/e/[id]/edit?conflict=13
Why source, not rich text. The web's doc editor round-trips through markdown (doc-edit/rich), and every mismatch between the rich model and the stored source has shown up as a phantom edit in a doc's history. A phone keyboard makes selection-based rich editing harder still. Dimmed marks keep the source visible and still readable, and the formatting bar means nobody has to type **. Saves stay version-checked, as on the web: the app never retries a refused write with a newer version, because that would discard Priya's edit without asking.

Files — list, upload, viewers

A file's viewer is chosen by the MIME type the node declared at upload, never by guessing from the name: images open full screen with pinch zoom, PDFs page by page, text and code in a monospace viewer with wrap, audio and video in the system player. Anything else gets an honest card with Share and Open in…. Uploads go to the node's file endpoint, one row each, with progress in bytes.

Files (k/files), with uploads in flightUploads sit above the grid, one row each, with progress in bytes and a Cancel. A refusal keeps the node's words and its reason. Thumbnails come from the node for images. Every other type shows its declared extension, never a fake preview. /[server]/[space]/k/files
Image viewer, zoomed (iOS; black in both themes)Full screen on black in both themes. Pinch or double-tap to zoom, the zoom level shows for a second, and swipe down dismisses back to where you were. One tap hides the chrome. The bottom row: Share (the file itself), Save to Photos, Copy link, Messages. /[server]/[space]/e/[id]/view
PDF viewer (Android, dark)The page stays white in dark mode because it is the document, not chrome. The page pill fades after scrolling stops, and the strip jumps to a page. Search finds text when the PDF has a text layer and says This PDF has no text to search when it does not. /[server]/[space]/e/[id]/view
A file with no viewerSays what it is, using the node's own MIME type, and offers the two honest ways out. Messages and Linked are still at the bottom, as on every entity page. /[server]/[space]/e/[id]

Drawings

A drawing opens to view, fitted to the screen. Pencil or finger draws only after you tap Edit, so panning a sketch never adds a stroke. Saving is version-checked like a doc.

Drawing in edit mode (iOS, Pencil)With an Apple Pencil connected, Pencil draws and a finger pans, so no mode switch is needed. Without one, the hint reads One finger draws · two fingers pan. The tool rail holds pen, highlighter, eraser, shapes and text. A selection is drawn dashed with handles. Each stroke autosaves after 2 s of stillness, as a version-checked write. /[server]/[space]/e/[id]/edit
Empty state (Android, dark)An empty list says what the kind is for and offers the verb. The FAB is Material's primary create. The count is absent, not "0", until the node has answered. /[server]/[space]/k/drawings

Graphs

A graph entity (for example Session graph: mobile app) is drawn on a canvas you can pan and pinch, with a List segment as the accessible equivalent: the same nodes, grouped by kind, with edges in words. Tapping a node selects it and shows its edges. A second tap opens the entity.

Graph canvas, root selected (Android)The root is green, the selection is gold and its edges are highlighted with their names. A hub shows its degree in amber (14 edges). More than five siblings of one kind fold into a dashed 6 more node, so a phone screen never draws a hairball. The controls are Zoom in, Zoom out and Fit. /[server]/[space]/e/[id]?view=canvas

Artifacts

An artifact is a published web page with revisions. On the phone it renders live in a sandboxed web view with no access to the tm8 session, the same isolation the web gives it, and the full-screen button lets the phone rotate to landscape.

Artifact page (iOS, dark)The page renders live in a sandboxed web view, inline, with a full-screen button. The revision picker lists r1–r5 with who published each. Opening an older one says Viewing r3 · not the latest in the bar. /[server]/[space]/e/[id]?rev=5

Memories, skills and spells: what teammates carry

These three kinds are short text that changes how agents behave, so each page puts the text first and then says who it applies to. A memory is one claim. A skill is a folder an agent can load. A spell is a reusable prompt with variables.

Memory pageThe claim reads as a quote, because it is what agents read verbatim. Who it applies to is stated, not implied. How often agents loaded it is not shown: the node does not count that, and a number here would be invented. /[server]/[space]/e/[id]
Skill page (Android, dark)The description first, then the skill's files (each opens in the code viewer), then the exact reference a composer inserts. This is the node's one reserved in-body reference, tm8://skill/<id>. /[server]/[space]/e/[id]
Spell page, Cast disabled with reasonThe prompt shows its variables in gold, and each variable lists its default. Cast is drawn disabled and the caption under it says why. The phone does not pretend to run a spell the node cannot run from here. /[server]/[space]/e/[id]

People: members and teammates

Avatar shape is provenance: a member (human) is round, a teammate (agent) is a rounded square. A teammate's profile states what it is (model, profile, credential), what it is doing now, and the persona it runs with. Every number comes from the node, or the profile says nobody counted it.

Teammate profile"Now" shows the live sessions and the claimed tasks, which are the node's own lists. The cost tile shows a dash and says why in words, because an absent count is not zero. New chat opens 03 chat's composer with this teammate picked, and Launch opens 04 sessions' launch sheet. /[server]/[space]/e/[id]
People (Android, dark)Members are round and teammates are rounded squares, with the live dot only on agents that have a live session. Each subtitle says something true and current, not a job title. The list scrolls on to the other five teammates. /[server]/[space]/k/members

Open questions for the owner
  1. Cast a spell from the phone needs a facade verb ("start a chat from a spell with these variable values"). It is drawn disabled until one exists. Should the node add it, or should Cast stay web-only?
  2. A general entity reference scheme. Today only tm8://skill/<id> is reserved. The editor inserts web-address links, which the app draws as chips. A tm8://e/<id> scheme would survive a host rename. Worth a facade widening?
  3. Doc byline. The contract has no "last editor" field, so the reader names only the creator. Should the node expose the author of the latest version?
  4. Offline drafts. This design allows none (Edit needs a connection). Keep that, or allow drafts that open the conflict view on reconnect?
  5. New routes /e/[id]/edit and /e/[id]/view are proposed here for the overview's route tree.
