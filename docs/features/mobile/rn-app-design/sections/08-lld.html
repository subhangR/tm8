08 · Low-level design

Low-level design: the React Native app

The engineering half of this document, written so an engineer can start apps/mobile in this repo from it. It settles the stack, what the app shares with the web and what it must not, the exact expo-router tree, the multi-server client, the kind registry, state and the write queue, the chat and terminal pipelines, navigation, push, budgets, tests and release, and it lists by operation name the server work the app needs. What is new against the web phone shell: one app holds many servers and talks to each one directly instead of through a same-origin relay, Back is a native stack per tab instead of browser history, and reads survive offline in SQLite while writes keep their mutation ids until the node confirms them.

Architecture at a glance

Five layers, each importing only from the layers below it. The app does not keep a second copy of the graph's rules: the contract, the route codec and the chat and receipt folds are the web's own modules, moved into a shared package (§2). Everything that draws is new and native.

Anatomy of a write: one screen, every layer

The screen below is the most ordinary thing the app does: a person moves a task while a teammate is editing the same task. Every numbered part comes from a different layer. If the app gets this screen right, the same mechanisms carry every other kind.

  1. Scope comes from the route. [server]/[space] params become the first two elements of every query key (['tm8.sh', spaceId, 'entity', id]). The subtitle names the server because the app can hold several (§4).
  2. The conflict banner. entities.commands.work answered version_conflict (409), and a CollabError of that code carries current: EntityDetail (packages/contract/src/contract.ts). The store rolls the optimistic move back, adopts current without a refetch, and says who changed what and what was not applied (§6).
  3. The version the next write guards on. v12 is EntitySummary.version. Every command sends it as expectedVersion; “Move again” re-issues on v12 with a new mutation id.
  4. Verbs come from the registry. KindConfig.verbs → verb registry → availability (server capability flags plus a per-node probe) → enabled, or disabled with a reason (L6, packages/tm8-ui/LLD.md §0).
  5. Optimistic ticks. entities.commands.tick with a fresh clientMutationId. The shared journal (project/journal.ts) captures the prior state and reconciles on the entity.upsert echo that carries the same id.
  6. Messages below the body for task, doc and session (KindConfig.messages, CONTRACT §5 ruling 8): the latest one from messages.list, “View all” from counters.messages, which the node counted.
  7. Linked, grouped by edge family. KindConfig.edgeFamilies over entities.context --sections connections. A chip pushes the entity's page; if that page is the entry directly below, the chip acts as Back (§9).
Why the banner and not a silent refetch. The web's honesty laws (L6/L7) forbid a screen that changes under the reader without saying so. A conflict is a fact about other people's work: Reviewer's tick is real, and the person's move did not happen. The banner names both. A refetch-and-retry loop would overwrite one teammate's work with another's, and it would do it quietly.

Decision · terminal rendererxterm.js in a WebView, not a native renderer, for v1 and v1.1. The WebView runs exactly those files. RN keeps the parts a phone needs natively: the grant mint, the keys bar, the text input, lifecycle and the clipboard. A native renderer comes back only if the WebView misses the §13 memory or latency budget on the low-end Android device, and that would be a decision to re-transplant the byte stack, not a refactor.

Rules the resolver keeps
  • Never signs in from a link. An unknown origin goes to add-server with the full URL shown and a probe. A link cannot add a server, pick an account or switch accounts on its own.
  • The kind picks the tab. A cold link opens as [kind's tab root, entity], so Back lands on the list (overview, native conventions).
  • Scope changes replace. A link into another server or space resets the tabs at the root, the way setSpace writes with replace on the web. Back never crosses a space boundary the person did not walk (Back Contract Q4).
  • Drops are said once. The codec reports dropped classes (dropNoticeText); desktop-only params such as pins and panel tabs produce one toast, never silence.
  • Strategy, never kind. The resolver branches on strategy (anchored, special) the way the web codec does (packages/tm8-ui/LLD.md §1.1). It is the one exception to “no kind literals”.

4 · Servers, sessions and sockets

A server on the phone is device-local. It is not the server entity: that one lives in a home space and is reached through its node's relay (servers.list, migration 261, packages/contract/src/servers.ts). The web reaches remote servers through the local node's same-origin relay because S4 refuses every cross-origin preflight (servers/server-key.ts). Native fetch sends no preflight, so the app talks to each origin directly. Bearer requests are also exempt from the S6 header check by construction (checkCsrf, packages/server/src/http/security.ts).

5.1 · Every list is a tree when the data nests

Owner ruling, 2026-10-28: the structure must show on the phone. 14 · Security

Asset or threatControl
Session tokensSecureStore only, this device only (not in backups, not migrated). Never in SQLite, logs, crash reports, analytics, push payloads or the WebView.
PTY grantsMinted per attach and given only to the bundled terminal page. Navigation away from it is blocked, there is no remote content, and bridge messages are zod-validated both ways.
Logs and analyticsThe logger redacts Authorization, tm8s_ and tm8-grant. patterns and never logs request bodies. Analytics is off by default; crash reports are scrubbed in beforeSend.
LinksNo automatic sign-in to any host. An unknown origin goes to add-server with the full URL and a probe. Link params are shape-gated by the codec and never executed. Other schemes are refused.
Transporthttps required except loopback (local), via ATS NSAllowsLocalNetworking and an Android network-security config. LAN http only in the development profile.
Pinning (optional, per server)SPKI SHA-256 pins captured on add when the person opts in. A mismatch is a refusal (“tm8.acme.dev presented a different certificate”) with no in-app override.
Agent versus human identityThe app is a human client. It signs in as cli (v1) or mobile (proposed), both inside HUMAN_AUTH_KINDS. It never presents an agent token and never acts as a teammate. Agents are drawn from the actor kind, never inferred.
Data at restOS data protection on the sandbox. Sign-out or removing a server deletes its rows, SecureStore entries and device registration. Sensitive screens are blurred in the app switcher (iOS) or set FLAG_SECURE (Android).
