02 · Shell

App shell, servers & spaces, onboarding, settings

Everything around the graph: how a phone finds a tm8 node, signs in, picks a space, moves between servers and spaces, and where every destination that is not a tab lives. New against the web phone shell: many servers in one app, each with its own sealed sign-in and an honest reachability word; a switcher where the web phone had none (DEF-003); four tab stacks kept per (server, space) instead of a drawer that reset the stack; Browse as the drawer turned into a screen, with its trees; and Settings grouped by who a change reaches — this phone, you, the space, the server.

First run: welcome and adding a server

On this phone a server is three facts: a name, an origin and a sealed pass. The list of servers lives on the device and is the switcher's list. Nothing is sent anywhere until the first URL is typed.

The web reaches other nodes through the local node's relay (/v2/server-connections/<name>/proxy), because a page may only talk to its own origin and the server deliberately refuses every cross-origin preflight. An app has no origin, so it talks to each node directly and keeps the registry on the device. The rules for names and URLs stay the web's, because the registry has the same shape. Adding a server no longer needs a space. On the web, servers.add files a server entity in a space; on the phone the list is yours alone, and sharing a server with a space is a separate, explicit act.

Sign in, and choosing a space

Sign in — password, refused, keyboard upUsername, not email: auth.login takes a username and a password, and email is profile data. A wrong user and a wrong password get one message, because the server merges them on purpose (failures.ts). There is no attempt counter, because nothing enforces one, and no reset link, because auth password requires the current password. With "Stay signed in" on, the app signs in as a cli-kind session (90 days) sealed in the Keystore/Keychain. With it off, it uses a browser-kind session (30 days) held in memory and revoked on sign-out. /sign-in/[server]/password
Scan the QR, or type its code — proposedThis copies the shape of tm8 link grant: the web's Sign-ins & devices shows a QR holding the origin and a one-time code (single use, 10 minutes, only the hash stored). The app shows which server and which account before anything is redeemed, and the same cells take a typed code. Needs a facade widening (auth.device.grant/.redeem); until it ships, both doors stay off. /sign-in/scan · /sign-in/[server]/code
Choose a spaceAfter sign-in. Each space has its mark, your role and its member count (from spaces.list). Atelier shows 3 Needs-you and 9 unread. Playground shows nothing — unreadTotal is null on spaces.list and its lazy spaces.navigation read has not run, and absent is not zero. The ask-to-join state is the invite door plus a share sheet: no join-request op exists. /sign-in/[server]/spaces
Space password — the real second gatetm8 has no 2FA. Its only second step is the space password (W5): auth.space.enter answers space_password_required. A wrong one gets "That space password was refused."; a locked login gets "An admin locked your login to Atelier." /[server]/[space]/enter
Signed out by the server · signing inWhen auth.session.get or any call returns unauthenticated, a sheet comes up over the cached screen; the stacks are not reset. The loading state says what it is doing (DEF-038). Being unreachable never signs you out — reachability and the session are different facts. /sign-in/[server]/password (sheet)
Every rule here comes from the node, not from a pattern library. auth.login mints a tm8s_ pass that is returned exactly once. The app seals it in the iOS Keychain or the Android Keystore, keyed by server, and never puts it in AsyncStorage. Session lifetimes are the server's own: browser 30 days, cli 90 days, link 90 days (SESSION_TTL_MS). That is where "90 days" comes from. Only browser and cli pass the human-only doors (HUMAN_AUTH_KINDS) that space links, credentials and servers require, so the app uses cli rather than inventing a kind. Under TM8_SPACE_SESSIONS=enforce, entering each space mints a pinned session with auth.space.enter, as the web does.

Servers & spaces — the switcher

The space button at the top left of every tab root opens one sheet: every server on this phone, the spaces on each, which servers answer, and what needs you where. Anatomy — /spaces, iOS light, with acme-node offline and local signed out:

  1. Grabber and detents. The sheet opens at medium with one server and at large otherwise. Swipe down, tap the scrim, or press Android Back to dismiss — the sheet goes before the screen does.
  2. Edit. Reorder servers and the spaces under each. The order belongs to this phone and is never written to a server.
  3. Server header. Its name, its reachability word (online · offline · unreachable · signed out · update needed) and when it last synced. ⋯ or a long-press opens the server menu.
  4. Active space. Brand mark and a check. Tapping another row switches space and dismisses the sheet; nothing in the old space is thrown away (see below).
  5. Counts, honestly. Red badge = Needs you (lane 07's count); grey text = unread from spaces.navigation. Playground draws nothing because nobody has counted it yet. A zero would claim a measurement nobody took.
  6. An offline server. Its spaces still open from cache, read-only. Writes queue with a pending pill (v2, per lane 08), and the cached badge turns grey: last known, not live.
  7. Signed out. A server with no pass lists no spaces, only "Sign in". A server needing an update reads "update needed" here and opens its card.
  8. Add a server. The first-run flow, presented over the sheet; on success, the new server's spaces appear in place.
All servers offline · long-press a serverAndroid, dark: an M3 bottom sheet with 28dp corners. The phone has a network but no server answers, so the banner and every header say so, and the cached spaces still open. If the phone itself has no network, the words change to "No connection" and "not checked": an unchecked server is never called offline. Long-press acme-node for its menu. /spaces
The tab shell — long-press the active tabAndroid, light. A long-press on the active tab lists that tab's stack, top first (cap 12); tapping an entry pops back to it, one destination and never a jump forward. Re-tapping the active tab pops to the root, and at the root it scrolls to the top. Inbox carries its badge. The iOS bar is drawn in Browse ① below. /[server]/[space]/(tabs)/work › …
This is a sheet because it is temporary and over your place (CONTRACT §4). It has no address of its own worth sharing, so it is never the subject of a share. The web phone shell had no space switcher and no sign-out at all, and every tap census scored it healthy (DEF-003); this sheet fixes that. Counts follow the drawer's ruling 5: SpaceSummary.unreadTotal is null on spaces.list by design, the measured number is a lazy per-space spaces.navigation read, and an absent number draws nothing. Offline is a state, not an error (principle 8): a server's word comes from the server kind's own vocabulary, and the cache stays usable.

acme-node · Platformoffline — rebuilt from cache: route + scroll per screen, read-only
  • What a switch does. The whole set of four stacks is swapped. You stay on the same tab. In the space you go to, you land where you last left that tab, or at its root the first time. Switching back to Atelier finds Work exactly where it was, PR #955 two screens deep, with its scroll position kept.
  • Memory. The three most recent sets stay mounted but frozen. Older ones are kept as routes plus scroll offsets and rebuilt when you return. The stack cap of 12 applies per stack.
  • Transition. Tab content cross-fades over 180ms (--dur-base) with no slide, because nothing moved in the stack. The space button's mark morphs, badges are read again, and the haptic is selection / SEGMENT_TICK. Under enforce, auth.space.enter runs first, and a space password sheet can interrupt the switch.
  • Back never crosses a switch. Back walks the current set's stack. On Android at a tab root it goes to Chats, then exits. A cold link into another space switches the set and opens [kind's tab root, entity] there (lane 07).
  • Across sets. Inbox's "All servers" segment is the one view that reads every set. The space button carries a dot when another (server, space) has a known Needs-you count; unknown draws no dot.
This overturns the web phone's ruling that a drawer destination resets the stack to [Chat, destination] (CONTRACT §5, ruling 3). There is no drawer any more: each tab owns a stack. Keying the stacks per (server, space) means a switch never destroys your place, which matters most when two servers are in play. The rest of the Back Contract is unchanged: open pushes, the cap is 12, sheets dismiss first, and nothing jumps several levels.
Tablet — not in scopeThe web ruled tablet-768 a known, accepted failure (CONTRACT §1); the open task "Desktop-shell reflow overflow (tablet-768)" owns it. The app ships phone layouts only. On iPad and Android tablets it runs the phone layout at phone width, with no split view, until a tablet arrangement is designed.

The grouping follows the web's settings redesign (2026-10-18): Account, Space, Server, each with a scope chip saying who a change reaches. The phone adds "This phone" for what never leaves the device. One divergence: the web puts Linked spaces under Account, because every sign-in on a link is yours. Rows that open only on desktop still list, with an honest refusal (phone-sections.ts): a row that disappeared would read as "this space has no such thing".

Decisions other lanes build on(1) Stacks are kept per (server, space); a switch swaps the set of four, and a cold link into another space switches first (lanes 07, 08). (2) The space button sits on every tab root: tap opens the sheet, long-press shows recent spaces, and a dot appears only for a known Needs-you elsewhere (lanes 03, 05, 07). (3) The Inbox tab badge is lane 07's Needs-you count for the active space; absent means no badge, never "0". (4) The app signs in as kind: cli, labelled with the device name, and seals the pass in Keychain/Keystore; pinned space sessions are minted per switch (lane 08). (5) The Browse search field filters destinations, and its first row hands the text to lane 07's search modal. (6) Settings pushes on the Browse stack; space sections live at /settings/space/[server]/[space]/…. (7) The server registry is device-local; a server entity page offers "Add to this phone" when the node is missing from it.
