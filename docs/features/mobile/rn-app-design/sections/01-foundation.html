01 · Foundation

Design system & component catalogue

Every other lane composes from one kit; this section is where the owner judges the atoms once. It documents tm8's neutral default tokens with measured contrast in both themes, the platform type scale and how it reflows under Dynamic Type and Android font scale, geometry per OS, every kit component as a specimen inside a 1:1 phone, the 33 kind glyphs, motion, gestures and haptics, accessibility, theming, and the iOS/Android differences in one table. New versus the web phone shell: system type instead of Hanken Grotesk and Newsreader, 44pt/48dp targets as a token rather than a retrofit, haptics, native sheet detents, a space style painted natively — and a contrast audit that found six of seven pill tones under WCAG AA on white.

Contrast, measured

WCAG 2.x ratios computed from the token values with the same luminance function the server's style lint uses (relativeLuminance in packages/contract/src/style.ts); soft fills composited over the background they actually sit on. Anatomy — the design-kit index

The foundation lane's one screen is the in-app specimen gallery every phone in this section is a page of. It ships in internal and preview builds only, so screenshot tests (lane 08) render the very specimens the owner judged here.

  1. Top inset — 47pt on this class, 59–62 on Dynamic Island models; read from the safe-area context, never typed. Nothing interactive lives in it.
  2. Top bar, 44pt — the back word names the previous screen ("‹ About"); trailing icon buttons are full 44×44 frames with a 24pt glyph and an accessibility label ("Preview dark theme", "More").
  3. Large title — 34/41 bold, −0.02em; collapses into the 44pt bar as content scrolls (the hidden centred title appears with a hairline). Android draws a 56dp bar with a left title instead.
  4. Search — 36pt field, 10pt radius, inside the 16pt gutters; on Android a 48–56dp pill.
  5. Section header — footnote caps, 600, +0.08em, ink-3; 20 above, 8 below. Announced as a heading.
  6. Row — 44pt minimum (48dp), 32pt kind tile or 36pt avatar, 12pt gap, title 17/22, optional meta 15/20, trailing value + 18pt chevron. The whole row is one target and one accessibility element.
  7. Hairline — 1px --line between rows; full-bleed on plain lists, inset 60 under a lead in grouped ones. Never the only thing that tells two controls apart.
  8. Status in the meta line — a pill is a dot and a word, 22pt high; here the gallery's own contrast lint ("6 below AA"), computed on the device from the painted token table.
  9. Home indicator — 34pt; content scrolls under it, controls stop above it. The fade at the bottom says the list continues.

Rows & trees

The row is the atom of every list in the app. Per the owner ruling of 2026-10-28, every list is a tree whenever anything in it nests: expanded to depth 2, a chevron on every parent, 20pt indent per depth, a hairline guide from the parent's chevron down its children, and a count summary on a collapsed parent. A child keeps its own full row.

Rows · iOSPlain, tall, unread (dot, weight and the word "unread" in the label), pressed, swiped, and the tree row. The collapsed parent says what it hides: "3 subtasks · 1 working". /dev/kit/rows
Trees · AndroidDark. Sessions group by root with each child's own liveness word; a collapsed root counts its children ("3 children · 2 live"). Tasks show depth 0/1/2; deeper levels stay folded with a count. Row 2 shows the Material ripple. /dev/kit/rows?layout=tree
Trees are drawn because the owner ruled it (2026-10-28: "the tree structure is not shown in the list — in the app it must be shown") and because the web drawer already does it — "an item with children has a ▸ and expands in place" (MobileDrawer.tsx). Tree vs flat is decided from data (does any row have a parent of its own kind?), never from a kind literal. The tap target for disclosure is the 20pt chevron plus the indent to its left, padded to 44×44; the rest of the row still pushes.

Status & identity — pills, chips, badges, avatars

Ruling · one status-tone mapping for every lane (2026-10-28)The kit drew working and done in the same green and the web carries three mappings. From now on one table, by meaning: green = moving now (working, live, running, checks passed) · amber = waiting on someone (waiting, stale, pending, queued) · red = stopped by a problem (blocked, failed, error, refused) · blue = with a reviewer or in flight (in review, review requested, checks running) · grey = not started or ended without landing (open, pulled, exited, cancelled, not running) · purple = landed (done, merged). The kit's .pill.done now paints purple (polish pass, 2026-10-28), so pill done and pill merged read the same. Priority and marks are dot-less (below). Why: a finished task must not look like a running one at a glance, and "landed" is one idea whether it is a task or a PR.
Status & identity · iOSEvery status word the node returns, grouped by the ruled tones (done is purple, with merged); priority and "default" are dot-less because they are not states. Humans round (Subhang, Priya, Marco, Lena), agents rounded-square; a live dot on either; a stack always names who is in it. /dev/kit/status
Status & identity · AndroidDark, 360dp. On paper every pill passes; on a card blocked, in review, merged and open drop under 4.5 — the second half of the contrast finding. /dev/kit/status
Kept from the web: status is colour + word (design language §1) and avatar shape is provenance, coloured by FNV-1a of the actor id, never the display name (kit/Avatar.tsx). Changed: the kit has four tints where the web has six tones (gap, below). Priority takes the registry's tone — low/medium grey, high/urgent red — with no dot, because the dot is reserved for state; the overview's gold "medium" pill should follow this. Iconography

Grid & stroke

24pt square, ~2pt optical padding, 1.75 stroke (kit .ic), round caps and joins, currentColor. Sizes: 16 inline in chips, 18 row trail, 20 in text and menus, 24 in bars, 26 iOS tab, 40 empty states.

When filled

Never for meaning. Two places only: the active tab on both OSes (HIG tab bars and M3's active destination are filled; proposed, kit gap), and dot glyphs (more, grip, palette). A filled kind mark would read as "selected" beside stroked ones — kind-art.ts says the same.

One set, both OSes

The same glyph set ships on iOS and Android, so a kind looks the same on the phone and the web. Platform idioms win only for chrome: share (iOS box-arrow / Android nodes), back (chevron / arrow), overflow (⋯ / ⋮).

Every icon-only control has an accessibility label that is a verb and its object ("Search Atelier", "New chat", "Share task") — never the glyph's name and never "button". A glyph never carries status alone: the word is always beside it.

  • Vars only. A style is foundation + vars + css (packages/contract/src/style.ts). The phone paints the vars that map onto its tokens (surfaces, ink, brand, status, terminal) and ignores css — sanitised web CSS cannot style native views — and size/radius keys, which are platform metrics here.
  • No fonts. The system face always. A style whose display face is a serif (Atelier's Newsreader) gets the platform serif — New York (ui-serif) on iOS, Noto Serif on Android — on large titles and entity titles only.
  • Always-dark stays dark. The terminal is painted from the style's dark sibling in both themes.
  • Contrast floor. The phone runs the server's lint (ink/paper ≥ 4.5, ink-3/paper ≥ 3) plus its own (ink-3 ≥ 4.5 because subtitles are 13–15pt). A failing key paints as published, Appearance shows the warning, and with iOS Increase Contrast / Android high-contrast text on, the failing key falls back to the foundation's value. Atelier light's ink-3 on paper is 3.12 — it trips this.
