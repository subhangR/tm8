The Dreamer

Memories are useful because they enter future sessions. That is also why stale or contradictory memories can quietly poison every session that follows.

Dreamer is tm8’s seeded memory-hygiene runtime. An enabled daily loop revisits the graph, marks suspect claims from pinned evidence, then consolidates chains into smaller working sets. The historical record stays intact.

01Rot compounds silently

Stale is not harmless

A memory can remain internally consistent and still stop matching the running system. If it stays in the injected set, the next session begins from yesterday’s world.

Contradiction spreads

When two injected claims disagree, an agent must spend context resolving them—or choose the wrong one. Without durable evidence, the same dispute repeats later.

02Two append-only moves

MARK

An evidence-bearing message or memory points to a suspect entity with a disputes edge. Its properties require quote, expected, observed, and pinnedVersion.

tm8 edge create <evidence-id> disputes <memory-id> --props <json-source>
CONSOLIDATE

A new memory points back to each predecessor with an acyclic supersedes edge. Reads resolve to the chain head; the mutable remembers association can then keep only that head in the injected working set.

tm8 edge create <successor-memory-id> supersedes <predecessor-memory-id> --props <json-source>

MARK and CONSOLIDATE name Dreamer’s runtime actions; they are not public CLI commands. The graph verbs shown above are real.

03The runtime, as shipped

Seeded actor
DRDreamerteammate is a real team_member entity. This plate covers its memory sweep, not its teammate anatomy.
Seeded loop
Dreamer daily sweep is a real enabled loop entity with schedule every 1d and lastError: null in the live 2026-08-20 snapshot.
Run history
A loop’s inbound triggered_by edges—from the tasks or sessions it caused—are its run history.
Evidence rule
disputes only accepts a message or memory source. The database schema requires the pinned comparison fields, so an evidence-free mark is structurally impossible.
Read rule
supersedes is memory → memory and acyclic. A successor marks its predecessor; reads resolve to the chain head.

Nothing is deleted. Consolidation adds a better memory and narrows the injected set. The old records remain queryable, and the database refuses Dreamer’s deletion path.
