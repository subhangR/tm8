Project mode uses the shared project root. Scratch mode uses an empty server-owned directory with no project. Worktree mode creates an isolated checkout and branch from a symbolic base ref. The session and task associate to the worktree through in_worktree; project-backed entities associate to the Space-local project through in_project.

  1. Link the ProjectResource to the Space.
  2. Spawn a worktree session from main.
  3. Work on its isolated branch.
  4. Checkpoint commits the entire WIP and posts a receipt.
  5. Rollback restores tracked work; untracked deletion requires force.
  6. Server reconciliation repairs allocation state but never infers merged or abandoned.

Drive the plate with the mode choices and transport bar. Arrow keys move through the workdir choices; the range input uses the browser’s native keyboard controls.

01Three coordinates, not three synonyms

PROJECT

The live checkout

Requires a ProjectResource. The session starts at the shared root, sees uncommitted files, and may collide with another project-mode session.

SCRATCH

The empty desk

Requires no project. The Server owns the directory. It is useful for graph-only or exploratory work that needs no source tree.

WORKTREE

The isolated lane

Requires a project. The Server provisions the checkout and branch from --base-ref; no caller-supplied path exists.

02Checkpoint makes rollback findable

session checkpoint

Commits the worktree’s entire WIP to its branch and returns the commit oid. A clean tree is still success: the checkpoint ref is HEAD. A created checkpoint writes a durable receipt on the session anchor.

session rollback

Restores the lane to a checkpoint. Tracked WIP is discarded by design; the previous commit remains reflog-reachable. Untracked files may exist in no commit, so deletion refuses unless you pass --force.

Irreversible edge.--force may delete untracked files that no commit can recover. Without it, rollback refuses instead of guessing.

03The server repairs evidence, not meaning

Startup reconciliation cross-checks allocation rows, Git’s worktree list, filesystem entries, graph entities, and live PTYs. Semantic lifecycle and disk health stay separate.

It mayIt never does
Repair a safe partial allocation or retry cleanup.Infer merged from a missing branch or directory.
Release a stale lease when no live PTY owns it.Infer abandoned from silence or a timeout.
Quarantine an unrecognized Git worktree without touching it.Delete a worktree it does not recognize.

A lane can be semantically merged or abandoned while cleanup is still pending. Reconciliation converges the allocation; it does not invent the semantic fact.

04Link the project; track the delivery later

project link links a ProjectResource into a Space. Pass that ProjectResource id to session spawn --launch-project. The resulting Space-local project entity is a different identifier domain.

Current output limitation.The frozen projects.link result carries the ProjectResource id and Space id, but not the per-Space projectEntityId. The CLI names that absence; it does not substitute one id for the other.
