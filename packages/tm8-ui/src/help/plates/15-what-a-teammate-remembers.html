What a teammate remembers

A teammate carries a durable working set through remembers edges. At spawn, you can add one-session memory with --memory; memories the task remembers arrive automatically after the persona working set.

A memory is a durable entity. Its evidence, scope, and limits travel with the statement.

1 / 5
  1. A memory is a durable entity with mechanism, subject scope, limits, and a measurement time.
  2. A teammate's remembers edges define its persona working set.
  3. The --memory flag injects an existing memory for this session only and writes nothing to the graph.
  4. Memories remembered by the task are automatically injected after the persona working set.
  5. The server launches one work session with the assembled working set.

01Three sources, three promises

Memory entity

Durable graph data. The live shape carries mechanism, subjectScope, doesNotEstablish, and measuredAt around the statement.

remembers

A mutable working-set association. Any entity may be the holder; the destination must be a memory. The edge associates context—it does not certify truth.

--memory

Appends existing memory entities to the persona's injected working set for this session only. It creates no remembers edge.

02The spawn says exactly what it needs

The flag accepts memory entity ids and may repeat. Supplying a task activates the second durable source: memories that task remembers.

tm8 — northlakepty
tm8 session spawn --teammate 01a09e10-3333-7333-8333-ccccccccccc3 \
  --task 01a09f21-4c00-7a11-8b2e-0d3f5a7c9e11 \
  --memory 01a09f60-3d30-7e44-8f51-4c7d9e1a2b33 \
  --workdir worktree
  1. Persona first. The teammate's graph-associated memories form the durable working set.
  2. Session append. Each --memory id joins this launch only; tm8 writes nothing back to the graph.
  3. Task follows. Memories the supplied task remembers are auto-injected after the persona working set.
Boundary, not a shortcut. If a memory should return through future launches, associate it durably with the right holder. A one-session --memory injection is intentionally not that association.
durable association — real syntax
tm8 edge create 01a09e10-3333-7333-8333-ccccccccccc3 remembers 01a09f60-3d30-7e44-8f51-4c7d9e1a2b33

03The memory carries its boundary

A memory is not a loose prompt fragment. Its live entity state records why the statement exists, where it applies, what it cannot prove, and when it was measured.

memory entity — live-shaped fictional data
{
  "id": "01a09f63-6a30-7b44-8c55-1d2e3f4a5b66",
  "kind": "memory",
  "title": "Loop follows password change",
  "version": 1,
  "state": {
    "kind": "memory",
    "mechanism": "Reproduced in the Northlake worktree.",
    "subjectScope": "Login redirect task.",
    "doesNotEstablish": "Other auth flows.",
    "measuredAt": "2026-08-20T08:10:00.000Z"
  }
}

Read the edge honestly

A holder's working set includes this memory. A teammate, task, session, or another entity can be the holder.

The edge does not make the memory true, freeze it forever, or prove it belongs in every session. Evidence and limits stay explicit on the memory itself.

04One graph rule across providers

Memory assembly belongs to tm8's server-hosted spawn surface, not to a model provider. The same session spawn flags feed teammates launched through claude-code or codex; provider choice does not change remembers semantics.

This page does not enumerate the model catalog. It teaches the working-set contract shared by the catalog.
