# Synthetic Game GPU benchmark

This standalone test page mounts the shipping `buildMapModel` and `WalkingMapView` / `MapScene` with deterministic synthetic inputs. It never reads the authenticated workspace, starts the tm8 server, or records private rows or screenshots. Production code is unchanged. A production Vite build is served temporarily on loopback and removed on completion.

The Node classifier/math/interaction checks are run **manually**, not wired into repository CI, with the exact `node --test` command below. CI retains its existing production UI checks; compare their failures against the base head before attributing them to these test-only files.

Before mounting the scene, the probe estimates browser rAF pacing from up to 40 callbacks (5s cap) and records the raw interval distribution and estimated Hz. This is a clock estimate, not hardware/display proof. Results near that cap are labeled as having unknown headroom. Interaction windows require observed player displacement during the D-hold plus a camera/overview change; failed input effects invalidate the window.

From a clean checkout, install the repository's locked dependencies with `bun install --frozen-lockfile`, then install the matching browser with `cd packages/tm8-ui && bunx playwright install chromium`. Run the commands below from the repository root. If using an existing browser binary, add `--chromium /absolute/path/to/chromium`.

On minimal Linux hosts Chromium also needs its usual shared libraries (`bunx playwright install-deps chromium` where authorized). This worker used already extracted libraries with `LD_LIBRARY_PATH=/tmp/libs/root/usr/lib/x86_64-linux-gnu` and Chromium 145 at `/home/tm8/.cache/ms-playwright/chromium_headless_shell-1208/chrome-headless-shell-linux64/chrome-headless-shell`. Those local paths are not required elsewhere. The report records the library-path override, browser command line, host load average and lack of reserved exclusive resources. The worker has no render nodes/display and only a QXL virtual PCI display; its native eligibility is always false.

If the worker's multiprocess browser crashes during setup, add `--single-process` together with `--software`. This explicit diagnostic mode uses `--no-zygote --single-process` and starts a fresh browser for each case/repeat. It is recorded in the report and forbidden for native runs. It measures a different process configuration and must not be compared as native production performance.

```sh
node --test packages/tm8-ui/e2e/game-gpu/core.test.mjs
node packages/tm8-ui/e2e/game-gpu/run.mjs --smoke --software --case space/taskland/representative --output /tmp/tm8-gpu-smoke
node packages/tm8-ui/e2e/game-gpu/run.mjs --software --expected-head "$(git rev-parse HEAD)" --output /tmp/tm8-gpu-baseline
node packages/tm8-ui/e2e/game-gpu/run.mjs --native-only --headed --expected-head "$(git rev-parse HEAD)" --output /tmp/tm8-gpu-native
tm8 artifact publish /tmp/tm8-gpu-baseline --name 'Game synthetic GPU baseline' --when-to-use 'Open when reproducing Game benchmark measurements or checking GPU eligibility' --summary 'Synthetic workload counts, renderer/device audit, raw frame/draw samples and exact reproduction provenance'
```

The full matrix is six maps (`hub`, `taskland`, `office`, `library`, `factory`, `town`) × two scopes (`space`, `story`) × two workloads. Representative = 64 content rows; large = 512. Taskland adds 16/128 live worker sessions and claim edges. Town adds 16/128 produced artifacts. Other maps rotate their relevant entity kinds; hub content rows are child-story portals. Taskland includes nested parents, done roots with open children, done/cancelled children, variable progress, missing estimates, attention/mailbox counts and dependency roads. The report records admitted places/groups/roads/robots/portals/asset instances separately from input counts, since filtering and viewport culling change rendered work. Inputs are byte-deterministic and each has a SHA-256 hash.

Defaults: 1440×960 viewport, fixed device scale factor and renderer DPR = 1, normal motion, visible focused page, 2s warmup after readiness, 10s windows, 3 repeats per workload, at least 30 complete rendered intervals. Each repeat gets a fresh browser/context/page with an empty HTTP cache; readiness uses Playwright request events without a separate CDP Network session. Readiness requires nonzero actual scene draws, the existing asset report showing no active loading/errors or unresolved imported-asset fallbacks, fonts ready, visible nonzero canvas, and 500ms HTTP quiet. Unknown asset aliases that use permanent procedural fallback remain recorded. Asset report, shadow enable/type, renderer size/DPR and memory are retained. There are no invented FPS pass marks.

Each repeat samples idle explorer view, then a scripted window: hold D for the first half, release it, toggle M overview and scroll +120, then let the second half settle. Actual position/camera observations are recorded; this is input coverage, not a guarantee that every collision layout permits movement. Event replay, new weighted acceptance/subtree construction, injected-clock rubble expiry, root status transitions, worker routes and shipping transitions are explicitly **unsupported at the baseline head**. Nested navigation, reload persistence and the authenticated graph adapter also require their owners' separate tests and a final integrated run. Static robot poses/ambient model animations and the production player are present; this benchmark does not claim full animation coverage.

`report.json` retains raw rendered intervals and per-window FPS, frame median/p95/p99, >33ms and >50ms counts, callback CPU time and draw-call distributions. Multiple drawing callbacks sharing a rAF timestamp are aggregated. Draw submissions include shadow passes and instanced calls (an instanced submission counts as one draw). Outside-rAF draws are counted separately and excluded from frame distributions. The first interval crossing the window boundary is excluded. Zero rendered intervals are explicitly invalid. This shipping Canvas renders continuously: a non-advancing render clock is labeled render_loop_stalled, and an advancing clock with too few complete intervals is labeled frame_interval_exceeds_window. Sparse windows retain the longest observed interval and remain invalid. Callback timing includes instrumentation and asynchronous driver submissions; it is not GPU execution time. This tool has no GPU timer query. Headless Chromium uses a synthetic frame clock, and display-paced FPS can hide headroom at the vsync cap. Physical refresh rate is reported only when Linux xrandr exposes it, otherwise unknown; it is never inferred from scene FPS. Compare repeat distributions and raw windows under matching browser, shadow and interaction conditions.

Native eligibility fails closed. It requires a headed browser, full expected SHA matching actual HEAD, clean checkout, a positively identified hardware renderer, accessible recognized physical device evidence matching Chromium's numeric vendor/device IDs (or macOS vendor plus host model in its device/renderer string), browser driver version, hardware-enabled WebGL/WebGL2, and valid samples. SwiftShader, llvmpipe, WARP and virtual/software identities or explicit `--software` always fail native eligibility. `--native-only` exits 2 on missing proof; it cannot silently fall back to a diagnostic run. macOS may remain unverified if Chromium omits driver version, even when Metal works; the diagnostic report explains this. Linux NVIDIA nodes without accessible DRM render nodes are likewise unverified. All headless results are diagnostic. No manual eligibility override is supported.

`--smoke` permits short windows for tool verification only and always makes native eligibility false. Non-smoke settings enforce at least 2s warmup, 10s samples and 3 repeats. `--case scope/map/workload` selects one workload for focused diagnostics and cannot make a full-matrix report native eligible. A failed readiness or invalid window remains in the report and sets exit 1; a setup/native-gate failure sets exit 2. Browser/server/temp-build cleanup runs in `finally`. Publish only the evidence output directory. `index.html` is a safe static synthetic report; its JSON contains exact head/main, dirty state, browser argv/device/driver, tool/fixture hashes, visibility and settings.

The GPU audit runs in the same browser after both sampled windows and before browser close. Its start/completion timestamps are bound to each window. Native classification requires the sampled unmasked renderer to equal the audited GL renderer, the active GPU (or first device when no active flag exists) to match host evidence, and a stable connected scene context. Missing, timed-out or mismatched audits, context loss and reported GPU restarts fail closed. Hardware-looking renderer strings without this proof remain unverified. The same late-audit order applies on hardware hosts.

On this worker, removing early SystemInfo or extra Network CDP setup alone did not resolve fixture failures; the underlying cause is unproven. Single-process software diagnostics are explicitly noncomparable with multiprocess or hardware runs. Browser shutdown is bounded, with forced termination restricted to the runner-owned browser process. Every failed case/window remains in the report; a partial report is not a completed baseline.

A first native-host run must check the byte-for-byte audited GL renderer and sampled UNMASKED_RENDERER strings: driver/backend suffix differences (including Metal) can deliberately fail closed. A null GPU crash counter means unavailable, rather than evidence of zero restarts. Software smoke draw counts rise after M overview exposes more scene work; the combined walking/overview/zoom window cannot attribute that increase to one feature, so it must not be read as a renderer regression. Forced browser cleanup entries include the case and repeat.
